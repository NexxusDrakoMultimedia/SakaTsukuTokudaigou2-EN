# l10n format: the public form of the translation (format version 1)

The public repository holds **English text, identifiers and hashes only**: no Japanese text, no Sega pixels (textures are
deltas, see `docs/texture-delta.md`).  The Japanese is read out of the player's own disc by `tools/l10n.py import` and every
string is checked against its recorded hash.  Tools: `tools/l10n.py`, `tools/verify_source_disc.py`, `tools/setup_from_disc.py`;
tests: `tools/test_l10n.py`.

| Form | Where | In git? | Read by |
|---|---|---|---|
| working form | `translation/*.jsonl`, `translation/refit/*.jsonl` (with `ja`), `translation/textures/**/*.pvr` | no (gitignored, local) | every existing tool (`build_patch`, `transwork`, `refit`, ...), unchanged |
| committed form | `l10n/*.jsonl`, `l10n/refit/*.jsonl`, `l10n/MANIFEST.json`, `l10n/disc-files.tsv`, `l10n/textures/**/*.vcdiff` | yes | `tools/l10n.py import`, `tools/setup_from_disc.py` |

`export` turns the first into the second (maintainer, from the full working tree); `import` rebuilds the first from the second plus the
disc (everybody else).  `import(export(x))` is byte for byte `x` (proven, section 9).

## 1. The hash

```
jah = hex( SHA-256( raw )[0:16] )          32 lower-case hex digits
```

* `raw` = the bytes of the string **exactly as they are on the disc** (Shift-JIS / cp932), **without** the terminator (no NUL, no
  record padding).  The text form (`ja`) is never hashed: the hash is over bytes, so an encoding round trip cannot change it.
* Algorithm SHA-256, truncated to the first 16 bytes (128 bits; collisions are irrelevant because the id, not the hash, is the key).
  Recorded in `l10n/MANIFEST.json` (`hash`) and fixed by `FORMAT = 1` in `tools/l10n.py`.
* Test vectors: `jah(b"") = e3b0c44298fc1c149afbf4c8996fb924`, `jah(b"abc") = ba7816bf8f01cfea414140de5dae2223`.

## 2. Key = id; the hash only verifies

A record is identified by its **id** `FILE#hexoffset` (`FLOW_PRG/MEETING.BIN#3f204`, `BCAST/BCAST.BIN#1a0b80`): the path below the disc root
and the byte offset of the string inside that file.  Two strings with the same Japanese text (a menu label "OK" in twenty places) have
different ids and keep their own English; two records may even have the same `jah`.  The hash never selects a record, it only proves
that the bytes at the id's place are the ones the English was written for.  A mismatch means another game revision or a stale record and
is reported (section 7).

## 3. Where the raw bytes of an id are (how every kind of record is keyed)

`tools/l10n.py` `raw_of()` is the normative implementation.  The record's own fields (`fmt`, `cont`, `max_bytes`) select the rule;
nothing is guessed from the disc.

| Kind (`fmt`) | Records | Raw bytes |
|---|---|---|
| overlay string (no `fmt`; textdb, "pointer table", "orphan", half-width or full-width alike) | 126,477 | from the offset to the first NUL of the file `FILE` (a `FLOW_PRG/*.BIN` or `ATFIRST/*.BIN` overlay image, or `1ST_READ.BIN`, `2_DP.BIN`) |
| `hwptr` (half-width katakana strings reached by a pointer or pool) | 114,074 | same rule |
| `recarr` (fields of fixed-stride record arrays: staff, players, municipalities) | 127,941 | same rule (the field is NUL padded; the id is the field's offset) |
| `gap` (curated strings the scans missed) | 23 | same rule; if `cont` is true (the Japanese text runs on into the next record without a NUL) exactly `max_bytes` bytes from the offset |
| 1ST_READ / 2_DP pointer strings (`ROOT__*.jsonl`) | 361 | same rule |
| `DPETC/MESSAGE.INI` | 849 | the offset is the first byte after the opening quote of a `N="text"` line; raw = up to the last quote of that line (CR LF / LF not included) |
| `ETC_DATA/BPINFO.BIN` | 5,321 | the 14-byte name field at the offset, up to the first NUL |
| `bcast` (`BCAST/BCAST.BIN`) | 30,083 | id offset = `sector * 2048 + offset inside the clip header sector`; the header (2048 bytes at LBA of BCAST.BIN + sector) holds a u32 table at 0x60 of text offsets; raw = the text at that offset up to the next table entry (last one: end of sector) or the first NUL |
| refit overlay (`l10n/refit/`) | 38,310 | none of its own: it names the id of a main record; `ja` is taken from that record and its hash is verified again |

The "uncovered" table records of `docs/uncovered-text.md` (the 242,015 `hwptr` / `recarr` records) are ordinary records of this table: they are NOT
English-equals-Japanese identities (they carry real English: romanised names, club words), so nothing is regenerated by running the extractors
at import; every one is read by id from the disc like all the others.  `tools/uncovered.py`, `textdb.py extract` and the `textfmt_*` extractors
are only needed to CREATE new records, never to restore existing ones.  The only identity records (`en` equal to `ja`) are 6 BCAST lines (section 5).

BCAST needs the disc image itself (the 630 MB file is not in `extracted/`).  Every other file is read from `extracted/` when present,
otherwise straight out of the ISO9660 volume of the image.

## 4. Text form of `ja` (needed only to rebuild the working form)

`ja` is a lossless text rendering of the raw bytes.  Two renderings exist because two families of tools wrote the working files; the
rendering used is a function of the source file (and can be overridden per record with `codec`):

* `textdb` (every `FLOW_PRG/*`, `ATFIRST/*` overlay record, all `fmt`s inside them): ASCII 0x20-0x7e as is except `<` which is always `<3C>`;
  0x0a is `\n` (a newline character); a cp932 two-byte character that round-trips and is at least U+0100 is the character; a half-width katakana
  byte 0xA1-0xDF is U+FF61 + (byte - 0xA1); **every other byte is `<XX>`** (two upper-case hex digits).
* `common` (`DPETC/MESSAGE.INI`, `ETC_DATA/BPINFO.BIN`, `2_DP.BIN`, `1ST_READ.BIN`, `BCAST/BCAST.BIN`): like `textdb`, but `<` is written `<3C>` only when two
  hex digits and `>` follow, and two-byte characters from U+0080 up (for instance the multiplication sign) are kept.
* Encoding back: `<XX>` is one byte, `\n` is 0x0a, everything else is cp932; both renderings are inverted by the same function.

`tools/l10n.py` carries frozen copies of both decoders (`decode_textdb`, `decode_common`); `test_l10n.py` checks them against `tools/textdb.py` and
`tools/textfmt_common.py` on random bytes, and `export` checks that every `ja` of the working form survives `decode(encode(ja)) == ja`.

## 5. Files

### 5.1 `l10n/<same name as the working file>.jsonl`

Line 1 is the **header record** of the file, then one record per line, in the order of the working file (so diffs stay local).  UTF-8, LF, no BOM.
Written compactly (`separators=(",", ":")`, `ensure_ascii=False`); the output of `export` is deterministic.

Header: `{"l10n":1,"kind":"main"|"refit","style":"compact"|"spaced","n":N,"final_newline":true,"src":"FLOW_PRG/X.BIN","ctx":[...]}`

| Field | Meaning |
|---|---|
| `l10n` | format version (1); a reader refuses another number |
| `kind` | `main` (a `translation/*.jsonl`) or `refit` (a `translation/refit/*.jsonl` overlay) |
| `style` | how the working file spells JSON (`compact` = `,` `:` ; `spaced` = `, ` `: `); the working form is restored byte for byte |
| `n` | number of records (a shorter file is refused as truncated) |
| `final_newline` | whether the working file ends with a newline |
| `src` | present when every id of the file has the same file part: ids are then bare hex offsets (`"id":"3f204"`); otherwise full ids |
| `ctx` | present when some `ctx` strings repeat (at least 3 times, at least 12 characters): records reference them by index (`"ctx":2`) |

Record (key order as written):

| Field | Meaning |
|---|---|
| `id` | `FILE#hex` (or bare hex, see `src`) |
| `jah` | the hash of section 1 |
| `same` | `true` when the English equals the Japanese text (the Japanese is never written); then there is no `en` |
| `en` | English text; **omitted when empty** (untranslated / skip) |
| `max_bytes`, `slot`, `refs`, `ctx`, `fmt`, `orphan`, `skip`, `cont`, `why`, `cls` | the structural fields of the working record, unchanged (`refs` = `null` is omitted in `main` files; a missing `refs` of a main record means `null`; an `int` `ctx` is an index into the header table) |
| `ko` | only when the working record's keys are not in the canonical order `id ja en max_bytes slot refs ctx fmt orphan skip cont why cls` (unknown keys last), or `en` / `refs` are missing: the list of its keys in the working order |
| `codec` | only to override the codec of section 4 for one record |
| `sty` | only when this line of the working file uses the other JSON style than the header `style` |

Refit overlay records (`translation/refit/`): `{"id","jah","en","why","cls"}`; `ja` comes from the main record with the same id.

**Guarantees enforced by `export`** (it writes nothing and exits 1 otherwise): no Japanese/CJK/full-width character in any value of any output
file (checked per field and over the whole output); `ja` encodable and round-tripping; unique ids; one of the two JSON styles per line.  The ctx
strings of the current data are ASCII (checked); `export` refuses a future ctx / en / why that contains Japanese.

### 5.2 `l10n/MANIFEST.json`

`l10n_format`, `game` (`title`, `product` = `HDR-0183`), `hash` (algorithm, input, truncation, encoding), `disc` (size, CRC-32, MD5, SHA-1, SHA-256 of
the five track files and of the cooked volume ISO: a copy of `[source.*]` of `tools/release.toml`), `disc_files` / `disc_files_sha256`, `files` (per l10n file:
record count and SHA-256), `totals`.  `import` refuses when `disc` differs from `tools/release.toml` (data and tool versions do not belong together).

The disc hashes are those of the Redump-style dump (Redump disc 27370) as the repo author measured them; the Redump database was not consulted
(`tools/release.toml`).

### 5.3 `l10n/disc-files.tsv`

`path  lba  size  sha256` of every file of the disc volume (1,216 entries incl. `IP.BIN` and `BCAST/BCAST.BIN`; names, sizes and hashes only).  Made by
`verify_source_disc.py --write-manifest`; used to check an `extracted/` folder file by file.

### 5.4 `l10n/textures/`

Texture deltas (VCDIFF against the original textures), owned by `tools/texdelta.py` (`docs/texture-delta.md`): one `<container>/<texture id>.vcdiff` per repainted texture (637 files, about 3.2 MB) plus `MANIFEST.tsv`
(repaint hash, original hash, delta size per texture).  They contain no original pixel run of 10 bytes or more; they are applied to the player's own dump (`tools/setup_from_disc.py`, or
`tools/build_patch.py --textures-delta l10n/textures`).  The full repainted PVRs (`translation/textures/`) are NOT committed.  Known point: 236 VQ textures carry a re-quantised codebook (`docs/texture-delta.md`).

## 6. Verifying the disc first

Nothing reads the disc before it is checked (`tools/verify_source_disc.py`): size + SHA-1 + SHA-256 of each track file (cue / gdi) or of the volume ISO against
`tools/release.toml`; if the tracks differ but the cooked volume (game data) equals `[source.volume_iso]` the dump is accepted (other pregap / audio storage),
else it is refused with every difference printed (exit 1; `l10n import` and `setup_from_disc` exit 3).  `--extracted DIR` checks an extracted folder against `disc-files.tsv`
(BCAST is skipped).  `tools/l10n.py import --no-verify` exists for development only.

## 7. Mismatch reporting

`import` never fails silently.  For every record it reports `FILE.jsonl  ID  kind: detail` with `kind` one of `hash mismatch` (the disc bytes hash to X, the data says Y),
`unreadable` (offset past the end of the file, no BCAST segment there, no INI value, file / sector unreadable) or, for refit overlays, `unknown id` / `hash mismatch`.
Default: stop after the first bad file (up to 50 lines); `--keep-going` checks everything and lists all (`--max-report N` lines on screen, `--report FILE` the complete
list); a summary with counts per kind follows and the exit status is 1.  A file with any problem is **not written**; an existing different output file is only replaced with `--force`.
A wrong revision shows up as thousands of mismatches in many files (on a disc that was already patched: 387,967 hash mismatches), a single bad record as one line.

## 8. Commands

```
python -I -X utf8 tools/l10n.py export   [--tdb translation] [--out l10n] [--only SUBSTR ..]      # maintainer: working form -> committed form
python -I -X utf8 tools/l10n.py import   --disc "My Game.cue" [--extracted DIR] [--l10n l10n] [--out translation] [--keep-going] [--report FILE] [--force]
python -I -X utf8 tools/l10n.py verify   [--disc ..] [--extracted ..] [--work build/l10n_rt] [--full]  # round trip on a snapshot of the current tree
python -I -X utf8 tools/l10n.py stats
python -I -X utf8 tools/verify_source_disc.py "My Game.cue" | --extracted DIR | --write-manifest l10n/disc-files.tsv "My Game.cue"
python -I -X utf8 tools/setup_from_disc.py "My Game.cue" [--extracted DIR] [--translation DIR] [--skip-extract] [--skip-textures] [--keep-going] [--force] [--dry-run]
python -I -X utf8 tools/test_l10n.py [--full]
```

`setup_from_disc.py` = verify the disc, extract every file but BCAST into `extracted/` (skipping files that already match the manifest), verify `extracted/`,
`l10n import` into `translation/`, then `texdelta.apply_all(l10n/textures, extracted, translation/textures)` (contract of `tools/texdelta.py`; skipped with a note while
`l10n/textures` does not exist), and prints the `build_patch` command.  Output of `extract` differs from the old `tools/extract.py` only in LF instead of CR LF line ends of `_filelist.tsv`.

### Translators: Japanese stays local

A translator who needs to see the Japanese runs `setup_from_disc.py` (or `l10n import`) on their own disc: the Japanese appears in the gitignored `translation/*.jsonl`
(and `extracted/`).  Never commit those; changes go through `l10n export` so that only English, ids and hashes are committed.  Required `.gitignore` entries (hygiene pass):
`/translation/*.jsonl`, `/translation/refit/*.jsonl`, `/translation/textures/`, `/extracted/`, `/build/`, plus any other unpacked game asset or text dump.  The pictures that show original art
(`docs/art-sample/club_edit_menu_{before,after,sheet}.png`, `tools/re/art6/plate_menu.png`, `tools/re/datatext/png/`) are ignored as well.

## 9. Measured on the current tree (2026-11-12)

* 194 working files (119 main + 75 refit): 398,598 main records (387,649 with English incl. 6 identity records, 10,949 without, 845 `skip`) + 38,310 refit records.
* `export`: 15 s; 60.9 MB of l10n against 78.8 MB of working files (jah 16.3 MB, ctx 12 MB, en 7.8 MB, ids 5.3 MB, the rest structural fields); no Japanese character in any file.
* `import` from `extracted/` + disc: 17 s; straight from the disc image only: 29 s; including `setup_from_disc` (verify 4 s, extract, manifest check, import) about 2.5 minutes.
* `l10n.py verify --full` (snapshot, export twice -> identical, Japanese scan CLEAN, import, compare): all 194 files byte-identical to the working form, from both reading paths
  (`extracted/` + disc, and disc only); about 1 minute.
* `import` onto a patched trial disc (`build/trial/bis_a`): refused with exit 3 by the disc check; with `--no-verify --keep-going` 426,520 problems listed by id (387,967 hash mismatches, 243 unreadable, 38,310 refit dependents).

## 10. Limits and notes

* A new kind of record whose raw bytes are not "to the first NUL" needs a rule in `raw_of()` (and a line in section 3); until then `import` reports hash mismatches for it.
* The working form must keep LF line ends and the two JSON styles; `translib.normalise_styles` / `tools/re/bld_normalise_jsonl.py` heal mixed files.
* `translation/*.tsv`, `translation/art/*.json`, `translation/refit/forms.tsv` / `_report.txt`, glossary and `tools/re/**` contain Japanese too and are NOT covered by this format (list in the repo hygiene report).
* Not covered: Japanese baked into textures (deltas, `docs/texture-delta.md`), fonts.
